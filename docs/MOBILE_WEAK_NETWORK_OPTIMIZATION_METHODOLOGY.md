# 移动端弱网优化方法论

> 基于 52im《移动端弱网优化专题（一）》至《（十五）》归纳，并结合当前协议标准与移动平台能力校正。
>
> 适用范围：移动 App 的 HTTP API、资源加载、图片/音视频、WebView、IM 信令和长短连接。本文独立于任何具体网络库或业务工程。

## 1. 总结

弱网不是单一的“信号差”，而是移动终端到目标服务之间任一环节的不稳定或高成本：本地网络、运营商 DNS、IPv4/IPv6 路径、跨网路由、CDN 节点、TCP/QUIC 建连、TLS 握手、源站处理、网络切换及应用自身的请求形态。

有效优化遵循一个闭环：

```text
真实请求观测
  -> 网络与故障归因
  -> 按风险选择策略
  -> 小流量实验与护栏监控
  -> 配置回滚或扩大范围
```

优化优先级应为：

1. 先保证可观测、可诊断和可回滚。
2. 再减少不必要的 DNS、连接、握手和数据传输。
3. 再针对 DNS、双栈、UDP 受限、切网、跨境等具体故障做动态策略。
4. 最后才考虑协议或内核层的进阶调优。

不能以无上限重试、关闭 TLS 校验、硬编码 IP 或固定内核参数换取表面成功率。

## 2. 弱网问题模型

### 2.1 移动网络的典型特征

| 特征 | 对请求的影响 | 应对方向 |
| --- | --- | --- |
| 高 RTT | DNS、TCP、TLS 和重试的等待被放大 | 缓存、连接复用、减少往返、端到端 deadline |
| 丢包和抖动 | TCP 重传、HTTP/2 队头阻塞、长尾增加 | QUIC 备选、请求分级、可靠降级 |
| 带宽波动 | 大资源和并发请求抢占关键请求 | 限并发、资源分级、断点续传、降质 |
| 网络切换 | 旧连接失效、IP 与路由改变 | 监听切网、连接迁移/重连、刷新地址 |
| DNS 不可靠 | 超时、劫持、污染、调度不准 | 受控 DNS、缓存、回退与地址健康度 |
| IPv4/IPv6 差异 | 双栈或 IPv6-only 环境中单栈失败 | Happy Eyeballs、双栈探测和分层统计 |
| UDP 受限 | HTTP/3/QUIC 无法使用 | 快速识别、短期熔断、回退 H2/H1 |
| 跨境/跨网 | 路由绕行、节点不匹配、长尾显著 | 全局节点、动态调度、分地域策略 |

### 2.2 请求链路

一次 HTTPS 请求通常经过：

```text
网络可用性 -> DNS -> 地址选择 -> TCP/QUIC 建连 -> TLS/QUIC 握手
-> 请求发送 -> 服务端处理 -> 首字节 -> 响应下载 -> 业务解析与渲染
```

任何阶段都可能导致“慢”或“失败”。因此，不能只记录总耗时，也不能将所有错误归为“网络异常”。

## 3. 方法论框架

### 3.1 四层闭环

| 层级 | 要解决的问题 | 关键产物 |
| --- | --- | --- |
| 观测 | 到底慢在哪里、失败在哪里 | 分阶段时延、错误码、网络上下文、请求轨迹 |
| 判定 | 是弱网、目标服务异常还是客户端策略错误 | 网络质量状态机、故障分类、置信度 |
| 执行 | 当前请求该如何更可靠地完成 | DNS/地址/协议/重试/降级决策 |
| 验证 | 优化是否真正改善用户体验且无副作用 | 分层 A/B、护栏指标、灰度和回滚 |

### 3.2 设计原则

- **数据优先**：没有分阶段数据和对照组，不发布“优化”。
- **端到端优先**：目标是用户任务完成和首屏体验，不是单一协议的理论时延。
- **按请求决策**：请求的幂等性、优先级、deadline、资源类型和用户是否等待，决定可采用的策略。
- **按网络上下文决策**：网络切换后不复用旧网络的地址、UDP 可用性和质量结论。
- **安全不降级**：Host、SNI、证书链与主机名校验始终保留。
- **成本受控**：重试、竞速、预连接、心跳、探测都必须有预算和关闭开关。
- **统一治理**：DNS、连接、协议、重试、日志和远端配置应由统一网络层治理，避免各业务各自实现。

## 4. 观测、诊断与弱网识别

### 4.1 每请求最小指标集

| 阶段 | 建议采集项 | 作用 |
| --- | --- | --- |
| 请求 | 请求 ID、trace ID、host、方法、资源类型、幂等性、优先级、deadline | 关联一次完整决策 |
| DNS | 解析器、缓存命中、TTL、候选 IP、IP 家族、耗时、错误 | 定位 DNS 及地址问题 |
| 建连 | TCP/QUIC、复用或新建、目标 IP、连接耗时、错误 | 分析连接质量和复用收益 |
| TLS/QUIC | TLS 版本、ALPN、会话恢复、0-RTT、握手耗时、证书错误 | 分析安全握手与协议能力 |
| HTTP | TTFB、状态码、响应字节、下载耗时、取消原因 | 分离网络慢、源站慢和业务失败 |
| 策略 | 计划协议、实际协议、地址选择、fallback 原因、重试次数、断路器状态 | 验证策略是否有收益 |
| 网络上下文 | 网络类型、网络切换序号、IPv4/IPv6、运营商/地域的脱敏标签 | 支持分层分析 |

所有耗时使用单调时钟。未测量的指标用“未知”表示，不能填 0。

### 4.2 被动采集优先

优先从真实请求中采集：

- HTTP RTT/TTFB：反映网络、服务端排队和处理的综合体验。
- Transport RTT：反映 TCP 或 QUIC 链路变化。
- 吞吐：使用足够的传输字节和时间窗口计算，排除缓存命中、小响应和不可解释的并发。
- 连接成功率、DNS 成功率、TLS 成功率、协议 fallback 率。
- 连接复用率、会话恢复率、0-RTT 尝试/接受率、资源取消率。

不要用一次请求、单个 ping 或信号格数直接判定弱网。对历史样本使用时间衰减的中位数或分位数，弱网进入/退出使用不同阈值和冷却时间，避免状态抖动。

### 4.3 主动诊断按需触发

主动探测会消耗流量、电量和服务端资源，只在连续失败、白屏、网络切换或低频抽样时进行：

1. 系统网络与默认路由是否存在。
2. Local DNS、受控 DNS 的解析是否成功，结果是否一致。
3. IPv4/IPv6 是否可达，目标 Host 是否可建立 HTTPS 连接。
4. 是否只 UDP 不可用，或目标服务本身不可用。
5. 诊断过程分阶段保存结果，不能等全部完成后才上报。

建议同时使用业务 Host、稳定探针 Host 和 DNS 服务 Host 做对照，以免把源站故障误判为弱网。

### 4.4 推荐状态机

| 状态 | 含义 | 建议动作 |
| --- | --- | --- |
| `UNKNOWN` | 样本不足或刚启动 | 使用保守默认策略，不做激进投机 |
| `HEALTHY` | 连续真实请求表现稳定 | 正常复用与有限预连接 |
| `DEGRADED` | RTT、失败率或吞吐持续恶化 | 收紧并发，关键请求优先，启用降级 |
| `DNS_FAILURE` | 解析或地址选择异常 | 启用 DNS 回退链，保留安全校验 |
| `UDP_BLOCKED` | H3/QUIC 不可达而 TCP 正常 | 暂停该网络上下文的 H3 尝试 |
| `ORIGIN_FAILURE` | 目标服务异常，其他探针正常 | 熔断/服务端容灾，不归为离线 |
| `OFFLINE` | 无可用网络或多种探测均不可达 | 快速失败、缓存展示、等待网络恢复 |

状态服务于策略调整，不覆盖单个请求实际结果。

## 5. DNS 与地址优化

### 5.1 DNS 优化目标

DNS 优化解决四类问题：解析时延、解析失败、劫持/污染、地址调度不准。它不是简单地“用 IP 代替域名”。

### 5.2 解析策略

推荐的受控回退链：

```text
有效内存缓存
  -> 受认证 HTTPDNS/DoH 结果
  -> Local DNS
  -> 已签名、短 TTL 的应急地址
  -> 明确失败
```

- 使用内存缓存降低启动和重复请求的 DNS RTT；缓存键包含 `host + 网络上下文 + IP 家族`。
- 遵守服务端 TTL；可短时返回 stale 结果并异步刷新，但必须限制最长过期时间。
- 应用启动和网络切换时，预取少量关键域名，不能无节制预取全部域名。
- HTTPDNS/DoH 使用 TLS，并确保响应来源可信。动态地址、TTL、撤销、灰度范围和配置版本必须可验证。
- HTTPDNS 不可用、结果失效或网络环境异常时，能回退 Local DNS；两者均不可用时才使用短期应急地址。
- DNS 请求失败不能覆盖仍有效的最后一次成功结果。

### 5.3 IP 选择

- 由服务端按地域、运营商、CDN 与容量给出候选地址；端侧结合近期连接成功率和耗时进行有限排序。
- 地址健康度至少按 `host + IP + 地址族 + 网络上下文` 记录，过期后衰减，避免错误永久化。
- 双栈网络遵循 RFC 8305 Happy Eyeballs：优先尝试 IPv6，同时对 IPv4 做错峰竞速；首个成功的连接获胜，其他尝试立即取消。
- IPv6-only/NAT64 环境必须纳入真实设备测试，不能仅用 IPv4 网络验证。
- 地址竞速设置候选数、延迟、总请求 deadline 和并发上限，防止弱网下放大流量与连接数。

### 5.4 IP 直连安全要求

即使连接目标是 IP，HTTPS 仍需使用原始域名作为 HTTP `Host`、TLS SNI 和证书主机名校验依据。禁止通过关闭证书校验、自定义宽松 `HostnameVerifier` 或 HTTP 明文降级实现 IP 直连。

## 6. 连接与安全握手优化

### 6.1 连接复用优先

移动网络中，一次新建 HTTPS 连接需要 DNS、TCP/QUIC 和 TLS 的多个往返。优先减少新建连接：

- HTTP/1.1 使用 Keep-Alive，并处理服务端关闭、空闲超时和最大生命周期。
- HTTP/2 在单连接上多路复用，同时监测 TCP 层丢包带来的队头阻塞。
- HTTP/3/QUIC 在单连接上并发 stream，可减轻 TCP 层队头阻塞，并支持连接迁移。
- 连接池按 origin、代理、TLS 配置和网络上下文隔离，控制每 host 的连接数和并发 stream 数。
- 实现健康检查、空闲逐出、最大寿命、服务端 GOAWAY/关闭处理和单飞建连，防止连接风暴。

### 6.2 预连接与备用连接

预连接和备用连接可以降低关键路径时延，但成本高：

- 仅对高概率、用户即将触发、收益可量化的关键 Host 使用。
- 在前台、充电、健康网络等条件下提高预算；弱网、低电量、后台限制时关闭或收紧。
- 统计命中率、空耗率、流量、电量、服务端连接数和失败率。
- 连接达到可用状态后取消同组的冗余建连。
- 所有开关均需远端可控，默认从小流量灰度开始。

### 6.3 TLS 优化与安全边界

- 优先启用 TLS 1.3，使用会话恢复减少重复握手成本。
- 0-RTT 只允许明确安全可重放的幂等请求；服务端必须具备重放防护。
- 旧 TLS 中的 False Start、特定 TCP Fast Open 等策略依赖实现与网络环境，不能作为跨端通用默认能力。
- 不因为弱网忽略证书链、域名、撤销或协议版本安全要求。

### 6.4 网络切换

网络切换后，旧路径的 DNS、连接和质量结论可能全部失效：

1. 监听系统网络回调，记录网络句柄与切换序号。
2. 将旧网络上的 TCP 连接标记为不可复用，取消低优先级投机任务。
3. QUIC 优先尝试路径验证/连接迁移；失败后对幂等在途请求进行一次受预算约束的重连或降级。
4. 新网络上刷新关键 DNS、重建有限连接，不继承旧地址的失败黑名单。
5. 用户取消、应用后台限制、服务端过载或 deadline 耗尽时，立即停止迁移和重连。

## 7. 协议与传输优化

### 7.1 HTTP 协议选择

| 协议 | 主要价值 | 风险与回退 |
| --- | --- | --- |
| HTTP/1.1 | 兼容性最高 | 多请求易产生更多连接或队头阻塞；使用 Keep-Alive |
| HTTP/2 | 多路复用、头部压缩 | TCP 丢包仍会影响同连接 stream；监测大流量抢占 |
| HTTP/3 | QUIC 独立 stream、切网迁移、减少 TCP 队头阻塞 | UDP 可能被阻断；必须快速回退 H2/H1 |

- 优先通过 `Alt-Svc` 或受控配置发现 HTTP/3，不对未知 Host 盲目发起 QUIC 探测。
- H3 失败需要区分 UDP 不可达、握手错误、证书错误、网络超时和源站错误。
- 为 `origin + 网络上下文` 建立短期 H3 断路器，避免在 UDP 受限网络反复失败。
- 协议 fallback 仅用于幂等或拥有服务端幂等键的请求，并共享一个总 deadline。

### 7.2 数据传输优化

- 合并可以安全合并的细小请求，批量请求/响应，减少往返和头部开销。
- 使用缓存、ETag/条件请求、预测加载和分页，避免重复获取数据。
- 对文本数据选择 gzip、Brotli、Zstd 或紧凑编码时，同时评估 CPU、耗电、解压时延和服务端成本。
- 已压缩的图片、视频、音频通常不再次压缩；应通过尺寸、质量、码率或分辨率降级减小负载。
- 大文件使用分块、校验、断点续传和合理并发；并发数随网络质量和服务端负载动态收紧。
- 为小型关键请求、普通 API、图片和大资源设置独立优先级队列，防止低优先级传输挤占用户操作。

### 7.3 传输层调优的谨慎原则

应用层通常不能安全、可移植地优化 TCP 内核参数。优先处理请求形态、连接复用、协议选择和服务端链路。固定 MSS、固定 Socket 缓冲、放大初始拥塞窗口、固定 RTO 等做法必须由系统/内核团队在可控环境验证，不能作为通用 App 策略。

## 8. 超时、重试、熔断与降级

### 8.1 端到端 deadline

每个请求使用单调时钟的总 deadline，并把剩余时间传给每个阶段：DNS、地址竞速、连接、TLS/QUIC、TTFB 和下载。应区分：

- 连接超时：建立底层连接的最长等待。
- 读写空闲超时：已有连接长时间无进展的保护。
- 首字节超时：服务端或链路迟迟没有响应。
- 总 deadline：用户可接受的整体等待上限。

超时值按请求优先级、交互状态、历史分位数和网络质量标定，不能仅按 2G/3G/4G 使用固定秒数。

### 8.2 重试

- 只重试可重试错误，且请求必须是幂等的，或服务端有业务幂等键和去重能力。
- 使用有限次数、指数退避、随机抖动、最大总耗时和每 origin 并发预算。
- DNS、连接、短暂网络中断、可恢复服务端错误可被分类处理；证书错误、用户取消、业务拒绝、参数错误不重试。
- 收到 `429`、`503` 或 `Retry-After` 时服从服务端节流，不在客户端放大流量。
- 网络切换、应用进入后台或 deadline 耗尽时中止重试链路。

### 8.3 熔断和 fallback

- 熔断键包含目标 origin、协议、地址族和网络上下文，避免一种网络的失败影响其他网络。
- 失败计数只包含可恢复、可归因的错误；成功应逐步恢复探测，而非永久封禁。
- fallback 需要记录原协议、失败阶段、剩余 deadline 和最终结果，防止“成功”掩盖质量下降。
- 非幂等写请求的降级必须由业务确认，不可由网络库静默重发。

### 8.4 业务降级

| 业务类型 | 弱网策略 |
| --- | --- |
| 首屏/API | 关键接口优先，缩减非关键字段，使用有效缓存 |
| 图片 | 低分辨率、渐进加载、延迟加载、缩略图优先 |
| 音视频 | 降码率/分辨率、缩短缓冲目标、分片与断点续传 |
| 下载 | 暂停或限速低优先级任务，支持续传和校验 |
| IM/实时信令 | 信令优先于媒体，序列化重连，避免心跳风暴 |
| WebView/白屏 | 关键资源优先、资源缓存、请求轨迹与失败快照 |

业务降级不能影响支付、身份、数据一致性和安全验证。

## 9. CDN、跨境、白屏与资源场景

### 9.1 CDN 与路由

- 多地域、多运营商和多 CDN 部署，减少跨网和回源路径成本。
- 基于 DNS/服务端调度提供候选节点；端侧通过成功率、建连耗时、TTFB 和地址健康度进行有限反馈。
- 云端节点拨测与真实端侧样本一起分析，单独按地域、运营商、网络类型、协议和资源域名统计。
- 节点切换、CDN 容灾、地址更新、回源策略和协议开关都应可灰度、可回滚。

### 9.2 跨境网络

跨境问题不应只看“网络差”：分别定位当地接入、Local DNS、国际出口、CDN PoP、TLS/QUIC、源站与资源域名。常见手段包括区域化 DNS 调度、当地 CDN/边缘节点、多线路容灾、适合当地网络的协议回退与更严格的流量预算。

### 9.3 白屏诊断

白屏不是单一 API 的失败。应记录页面打开前后的：

- HTML/API、图片、字体、脚本、配置和 CDN 资源的请求时序。
- 缓存命中、DNS/连接/TTFB、状态码、响应大小和解析/渲染失败。
- 网络切换、资源取消、超时、协议 fallback 和 WebView 错误。
- 最近关键请求的环形缓冲快照。

白屏后的 ping 或探测只能辅助判断；根因应以白屏前的真实资源请求轨迹为准。

## 10. 统一网络库与策略平台

专题实践共同说明：大规模 App 必须让 DNS、连接、协议、日志、重试和远端策略在统一网络层收敛。推荐的分层：

```text
业务层：请求优先级、幂等键、缓存/降级语义
    -> 统一网络 API：deadline、取消、错误模型、指标事件
    -> 策略层：质量判定、DNS、地址、协议、重试、熔断
    -> 传输层：H1/H2/H3、TLS、连接池、DNS Resolver
    -> 平台层：网络回调、存储、调度、诊断与上报
```

远端策略至少具备：

- 版本、签名、适用范围、有效期、灰度比例和一键回滚。
- DNS/地址、协议、超时、重试、熔断、预连接和降级的独立开关。
- 对机型、系统版本、网络、地域、运营商和业务版本的受控匹配。
- 配置失败时保留本地安全默认值，不能让策略服务成为单点故障。

## 11. 验证与发布

### 11.1 故障注入矩阵

| 场景 | 注入条件 | 必测结果 |
| --- | --- | --- |
| 正常网络 | Wi-Fi、蜂窝、IPv4/双栈/IPv6-only | 成功率、P95/P99、连接复用和无回归 |
| 弱网 | 高 RTT、抖动、限带宽、2%/5% 丢包、乱序 | 长尾、deadline、重试放大和业务降级 |
| DNS | 超时、错误 IP、污染、HTTPDNS 不可用、TTL 过期 | 回退链、地址选择与安全校验 |
| 协议 | UDP/443 阻断、H3 握手失败、TCP 失败 | H3 熔断、H2/H1 fallback、幂等性保护 |
| 切网 | Wi-Fi 与蜂窝切换、IP 变化、NAT rebinding | 连接迁移/重连、在途请求恢复 |
| 服务端 | 429/5xx、慢首字节、半开连接、CDN 故障 | 熔断、降级、取消和资源回收 |
| 稳定性 | 高并发、长跑、频繁建连/销毁 | 崩溃率、内存泄漏、句柄泄漏、竞态 |

### 11.2 灰度指标

每项优化按网络、地域、运营商、IPv4/IPv6、协议、资源类型和请求优先级分层比较。

**主指标**：用户任务成功率、关键请求成功率、首屏/白屏率、TTFB/Total P95/P99、切网恢复时长。

**护栏指标**：请求数、重试放大率、预连接空耗率、fallback 率、服务端 QPS、流量、耗电、崩溃率、TLS/证书错误率。

**回滚条件**：主指标无明显改善，或任一护栏超过预设阈值，即自动关闭策略并保留诊断证据。

## 12. 不应直接采用的做法

| 做法 | 风险 | 推荐替代 |
| --- | --- | --- |
| 固定 MSS、Socket 缓冲、初始拥塞窗口 | 破坏系统对 PMTU、BDP 和网络的自动适配 | 控制数据量、复用连接、优化服务端链路 |
| 固定 RTO 或统一超时 | 快网体验被拖慢，弱网又可能过早失败 | 总 deadline 加分阶段动态超时 |
| `tcp_tw_recycle`/`tcp_tw_reuse` 作为通用解 | 前者已废弃，NAT 环境会误伤合法连接 | 连接复用和服务端容量治理 |
| 无条件 `TCP_NODELAY` | 可能增加小包与拥塞成本 | 合并业务写入，按实验决定 |
| Hook 系统 DNS/修改 ELF 接管解析 | 系统升级、第三方 SDK 和稳定性风险高 | 在统一网络库的 Resolver 层实现 |
| 关闭证书/主机名校验或降级 HTTP | 中间人攻击、隐私与数据完整性风险 | 保留 Host、SNI 和严格证书校验 |
| 0-RTT 承载写操作 | 可被重放 | 仅显式幂等请求使用 |
| 无限重试、无限竞速、无限预连接 | 流量、电量、服务端压力和故障放大 | 限次数、限并发、限 deadline、可回滚 |

## 13. 落地检查清单

### 基础能力

- [ ] 每请求具有分阶段时延、真实协议、目标地址、错误阶段和网络上下文。
- [ ] 具备请求取消、端到端 deadline、幂等性声明和可区分的错误模型。
- [ ] 指标有采样、脱敏、聚合和分层看板。
- [ ] DNS、连接、协议、重试与降级由统一网络层治理。

### 弱网能力

- [ ] 使用真实请求数据进行网络质量识别，并有状态抖动保护。
- [ ] 具备 HTTPDNS/DoH、Local DNS、短期应急地址的受控回退链。
- [ ] 支持 IPv4/IPv6 Happy Eyeballs、地址健康度和网络切换后的刷新。
- [ ] 支持 H3/H2/H1 的幂等 fallback、UDP 受限识别和短期熔断。
- [ ] 连接池、会话恢复、切网重连/迁移和资源优先级均有验证。

### 发布治理

- [ ] 所有策略均配置化、签名、灰度、可观测且可一键回滚。
- [ ] 弱网、DNS、UDP 阻断、切网、IPv6-only、跨境和服务端故障均有自动化测试。
- [ ] 发布看板同时包含成功率、尾延迟、流量、电量、服务端负载和安全护栏。
